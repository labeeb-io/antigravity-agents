# لبيب — ميثاق تسليم الإصدار التجريبي الأول (v0.1)
**تاريخ الاعتماد:** 30 سبتمبر 2026 | **الحالة:** ميثاق مجمد رسمي لحسم نطاق الإصدار (Release Contract)  
**المرجع:** مسودة متفق عليها مع صاحب المنتج والمؤسس لحسم ما يدخل وما يخرج من النسخة الأولى.

---

## 1. القيمة الأساسية المتعهد بها للنسخة (Core Value Promise)
يستطيع مستخدم عربي (بما فيه الصحفي المستقل أو الباحث) فتح واجهة لبيب، إدخال خبر أو ادعاء محدد، والحصول على نتيجة مسندة إلى أدلة ومراجع موثوقة قابلة للفحص والتحقق.  
يعمل هذا النظام فوق قاعدة بيانات مراجع ومصادر إخبارية مستمرة التحديث؛ ولا يُعتبر تصفح حزمة بيانات ثابتة أو الحصول على إجابة ذكاء اصطناعي عامة بلا مراجع دقيقة تحقيقاً لهذا التعهد.

---

## 2. الحدود الصارمة للنطاق (Frozen Scope Boundaries)
- **المسموح به حصراً:** واجهة ومسارات لبيب القائمة حالياً في واجهة الاستوديو (`Studio`)، ومصادره وبنيته التحتية الحالية.
- **سياسة الوصول:** إتاحة عامة للرحلة الأساسية مع الاحترام الكامل لعزل وحماية المحتوى المرجعي المقيد.
- **الممنوع منعاً باتاً (خارج نطاق v0.1):**
  - لا خطط تسعير أو اشتراكات مدفوعة جديدة.
  - لا بوابات مستقلة جديدة (كإعادة بناء بوابة الصحفيين).
  - لا إضافة مزودي ذكاء اصطناعي أو محركات بحث بديلة.
  - لا إعادة بناء معمارية لنظام التنسيق (`orchestration`).

---

## 3. رحلة القبول المعتمدة (Acceptance User Journey)
تبدأ الرحلة وتنتهي وفق المسار الميداني التالي دون أي التفاف:
1. فتح واجهة الاستوديو بالعربية: `https://labeeb.io/dashboard/studio`.
2. إدخال نص ادعاء عربي محدد (أو رابط مدعوم).
3. ضغط زر الإرسال وبدء جلسة تتبع ذات معرف رقمي مستقر.
4. ظهور نتيجة واضحة (حكم أو بيان صريح بنقص الأدلة).
5. فحص الأدلة ومصدر كل استنتاج ورابطه الأصلي بالعربية.

---

## 4. معايير الإطلاق الستة (The 6 Release Criteria)

| المعيار | الاسم الوظيفي | الدليل الميداني الإلزامي لاعتبار المعيار ناجحاً (PASS) |
|:---:|---|---|
| **المعيار 1** | **بدء جلسة التحقق** | مستخدم عادي يرسل ادعاءً عربياً في الاستوديو، فتبدأ جلسة عمل ذات معرف رقمي مستقر دون ظهور خطأ أو سقوط صامت للواجهة. |
| **المعيار 2** | **ظهور النتيجة وتتبعها** | نفس الطلب يصل إلى نتيجة واضحة أو إعلان صريح بنقص الأدلة؛ مع حفظ نص الادعاء وسياقه وربط النتيجة برقم الجلسة الأصلي. |
| **المعيار 3** | **دقة الأدلة والمراجع** | استرجاع مصادر مرتبطة حقيقة بالادعاء، مع اسم الناشر والرابط الأصلي والتواريخ؛ وتمييز حكم المصدر الأصلي عن تحليل لبيب، وتجنب إصدار أحكام قاطعة بلا سند. |
| **المعيار 4** | **سلامة الواجهة واللغة العربية** | إدخال النص، وعرض النتائج، وسرد الأدلة والمصادر تكون كلها واضحة باللغة العربية وباتجاه قراءة سليم (RTL)؛ مع ضمان عدم تسريب بيانات المراجع المحمية. |
| **المعيار 5** | **حداثة قاعدة البيانات والمصادر** | إمكانية استرجاع مرجع معروف بنجاح؛ وإثبات تشغيل دورة التحديث التلقائي للمصادر لدورتين متتاليتين على الأقل وتخزين مادة جديدة قابلة للاسترجاع دون تدخل يدوي. |
| **المعيار 6** | **تطابق النسخة العاملة مع الكود** | ربط واجهة الموقع وخدمات الـ API والخدمات المساندة بهويات النسخ البرمجية المنشورة فعلياً (Commit SHAs)؛ واجتياز رحلة القبول على نفس النسخة المنشورة، مع توثيق إعدادات التشغيل وآلية التراجع عند الطوارئ. |

---

## 5. قواعد جمع الأدلة والإثبات
- لكل فحص معيار يجب تسجيل:
  - رقم المعيار الصريح.
  - النتيجة الفنية: **ناجح (PASS)** / **فاشل (FAIL)** / **متوقف بمانع (BLOCKED)** / **مجهول (UNKNOWN)**.
  - رقم الـ Commit SHA الفعلي لكل مكون تم فحصه.
  - البيئة المستهدفة وتوقيت الفحص بالدقيقة.
  - المدخلات الدقيقة، خطوات إعادة التكرار، والنتيجة المرصودة في المتصفح أو سجلات الخادم.
- **تنبيه حاسم:** رقم SHA في مستودع GitHub لا يثبت بمفرده ما هو منشور على الخادم الحي.

---

## 6. مبررات العمل البرمجي (ما يسمح بكتابة الكود)
- يُسمح بكتابة الكود **فقط** عند وجود **فشل مثبت بدليل** ضد أحد المعايير الستة، أو لإجراء فحص محدود ينقل معياراً مجهولاً (`UNKNOWN`) إلى نتيجة مثبتة.
- يُمنع كتابة الكود لمجرد غياب الدليل أو بناءً على افتراضات نظرية.
- المعايير التي لم تصل إليها الرحلة بعد لا يجوز تحويلها إلى عيوب مفترضة؛ أول عائق في مسار الرحلة هو وحده الذي يقود المهمة البرمجية التالية.
