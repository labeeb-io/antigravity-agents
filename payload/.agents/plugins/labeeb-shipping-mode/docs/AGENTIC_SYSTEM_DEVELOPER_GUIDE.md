# دليل المطور: بنية وتشغيل المحرك الوكيلي (Labeeb Agentic Engine)
**تاريخ التحديث:** 30 سبتمبر 2026 | **النطاق:** الإصدار التجريبي الأول `v0.1 Public Beta`
**المرجع المركزي:** `tasks/release-v0.1/` | **الحالة:** معتمد وجاهز للتشغيل

---

## 1. الفلسفة المعمارية ومفهوم «العقل الوكيلي»

صُمم هذا النظام لتحويل وكيل الذكاء الاصطناعي من مجرد أداة محادثة عامة (Chatbot) إلى **محرك شحن برمجي منضبط وعالي الإنتاجية (Shipping Engine)** يركز حصراً على إنهاء وإطلاق النسخة الأولى من مشروع «لبيب».

### الركائز الأساسية للنظام:
1. **التركيز على مهمة واحدة (`WIP = 1`):** يمنع النظام فتح أكثر من مهمة برمجية نشطة في نفس الوقت لتجنب التشتت وتداخل الأكواد.
2. **الصفر تكرار (Zero-Boilerplate):** المطور لا يكرر كتابة البرومبتات أو نقل سياق المشروع يدوياً؛ تفعيل الأدوار يتم فوراً بأوامر سريعة أو عبارات طبيعية.
3. **الأتمتة تقترح، والإنسان يقرر (Human-in-the-loop):** تفصل بوابات موافقة واضحة بين مراحل التخطيط والتنفيذ والتدقيق.
4. **الفصل التام للحياد والتدقيق (Independent Audit):** مدقق الجودة لا يلمس الكود البرمجي نهائياً، بل يفحص تجربة المستخدم الفعلية كطرف مستقل.
5. **ديناميكية المسارات بالكامل (Dynamic & Relative):** لا توجد مسارات مطلقة (`absolute paths`) ولا أسماء سبرينتات ثابتة في الكود، كل شيء نسبي وقابل للتكيف مع أي بيئة عمل.

## 2. الهيكلية التقنية للعقل داخل Antigravity (`agt`)

يتكون العقل داخل Antigravity من خمس طبقات متناسقة:

```
┌─────────────────────────────────────────────────────────────┐
│ 1. طبقة القواعد (Rules)                                     │
│    .agent/rules/release_governance.md (تُحمّل تلقائياً)    │
├─────────────────────────────────────────────────────────────┤
│ 2. طبقة الخطافات الآلية (Hooks)                             │
│    .agent/hooks.json                                        │
│    ├── PreInvocation  ──> inject-release-state.sh (حقن)    │
│    ├── PreToolUse     ──> guard-governance-files.sh (حماية) │
│    └── PostToolUse    ──> auto-lint-check.sh (فحص تلقائي)  │
├─────────────────────────────────────────────────────────────┤
│ 3. طبقة مسارات العمل (Workflows)                           │
│    .agent/workflows/                                        │
│    ├── /lead           (منسق الإطلاق)                       │
│    ├── /exec           (مهندس التنفيذ)                      │
│    ├── /audit          (مدقق الجودة المستقل)                │
│    ├── /release-cycle  (دورة الإطلاق الموحدة)              │
│    └── /manager-handoff (تفويض المهام لأدوات أخرى)          │
├─────────────────────────────────────────────────────────────┤
│ 4. طبقة السكربتات التنفيذية (Scripts)                       │
│    .agent/scripts/                                          │
│    ├── pre-flight-check.sh  (فحص الجاهزية والحاويات)        │
│    └── smart-delegate.sh    (توجيه المهام الذكي)            │
├─────────────────────────────────────────────────────────────┤
│ 5. مصدر الحقيقة وحالة المشروع (Single Source of Truth)      │
│    tasks/release-v0.1/                                      │
│    ├── 00_RELEASE_CONTROL.md  (لوحة المتابعة الحية)        │
│    ├── 01_RELEASE_CONTRACT.md (ميثاق المعايير الستة)       │
│    └── sprints/               (وثائق السبرينتات الديناميكية) │
└─────────────────────────────────────────────────────────────┘
```

## 3. تفاصيل المكونات الداخلية وكيفية عملها

### أ. طبقة القواعد (`.agent/rules/release_governance.md`)
- تُحمّل هذه القاعدة تلقائياً في ذاكرة الوكيل مع كل جلسة محادثة.
- تحدد وضع العمل: `Shipping Mode`.
- تعرف الأدوار الثلاثة (Lead / Exec / Audit)، وأوامر السلاش ومحفزات التفعيل باللغة الطبيعية.
- تضبط قيود التعديل وحدود نطاق العمل.

### ب. طبقة الخطافات الآلية (`.agent/hooks.json`)
تعمل هذه الخطافات تلقائياً في خلفية كل عملية يقوم بها الوكيل:
1. **خطاف ما قبل الرد (`PreInvocation`):**
   - ينفذ سكربت `.agent/scripts/inject-release-state.sh`.
   - يقرأ لوحة المتابعة `tasks/release-v0.1/00_RELEASE_CONTROL.md` ديناميكياً.
   - يحقن رسالة سياق لحظية في بداية رد الوكيل توضح: رقم المهمة النشطة، اسمها، الموانع المعلقة، والمرجع المعتمد.
   - **الفائدة:** لا ينسى الوكيل أبداً المهمة الحالية حتى بعد ضغط السياق (Context Compaction).
2. **خطاف ما قبل الأداة (`PreToolUse`):**
   - ينفذ سكربت `.agent/scripts/guard-governance-files.sh`.
   - يعترض أي محاولة لتعديل ملفات الحوكمة الأساسية (`00_RELEASE_CONTROL.md`, `01_RELEASE_CONTRACT.md`, `.agent/rules/`, `.agent/workflows/`, `AGENTS.md`).
   - يعيد قرار `decision: "ask"` فيظهر تنبيه في الواجهة للمطور يطلب موافقته قبل السماح بتعديل الملف.
   - **الفائدة:** يمنع الوكيل من تعديل قواعد اللعبة أو شطب المهام ذاتياً دون موافقة المؤسس.
3. **خطاف ما بعد الأداة (`PostToolUse`):**
   - ينفذ سكربت `.agent/scripts/auto-lint-check.sh` للتحقق الآلي غير المعطل بعد أي تعديل.

### ج. طبقة مسارات العمل (`.agent/workflows/`)
- تحتوي على قوالب التعليمات المتخصصة لكل دور.
- كل دور له ملف Markdown منظم ومربوط بأمر سلاش (`/command`) ويحتوي على خطوات واضحة ومحددة.

## 4. دليل التشغيل اليومي ضمن Antigravity

### كيف تدير عملك اليومي؟

#### 1. مراجعة الموقف (أقل من 10 ثوانٍ)
اكتب في المحادثة:
```text
/lead
# أو بعبارة طبيعية: "وين وصلنا؟" أو "شو المهمة التالية؟"
```
- **سلوك الوكيل:** يقرأ لوحة المتابعة ويقدم ملخصاً من 4 أسطر فقط:
  1. المهمة النشطة حالياً.
  2. الهدف منها والمانع التقني المرتبط بها.
  3. الأداة المحددة للتنفيذ.
  4. القرار أو التوجيه المطلوب منك.

#### 2. بدء البرمجة والتنفيذ
اكتب في المحادثة:
```text
/exec
# أو بعبارة طبيعية: "ابدأ بالتنفيذ" أو "صلح الخلل"
```
- **سلوك الوكيل:**
  1. يشغل سكربت فحص الجاهزية `.agent/scripts/pre-flight-check.sh` للتأكد من عمل خدمات Docker ونظافة المستودع.
  2. يلتزم بالملفات المسموح بتعديلها حصراً وفق التذكرة المعطاة.
  3. يطبق التعديل البرمجي المطلوب مع مراعاة إرشادات `CODING_GUIDELINES.md`.
  4. يشغل أوامر الفحص الآلي محلياً (PHPUnit / Pytest).
  5. يقدم ملخصاً بالتعديل ونتائج الفحص، ويطلب إحالة المهمة للتدقيق.

#### 3. التدقيق والتحقق المستقل
اكتب في المحادثة:
```text
/audit
# أو بعبارة طبيعية: "فحص" أو "اشتغل؟" أو "تأكد من النتيجة"
```
- **سلوك الوكيل:**
  1. **يمتنع تماماً عن تعديل أي كود أو إعدادات.**
  2. ينفذ فحصاً حياً على تجربة المستخدم (Curl / متصفح / واجهات).
  3. يفحص سجلات الخادم والمتصفح.
  4. يوثق الدليل الرقمي (Commit SHA وتاريخ الفحص ومخرجات الاستجابة).
  5. يصدر حكماً صريحاً: `PASS` أو `FAIL` أو `BLOCKED` في تقرير رسمي داخل `tasks/release-v0.1/reports/`.
  6. إذا كان الحكم `PASS`، يقدم مقترح تعديل محدد بصيغة `Git Diff` لتحديث لوحة المتابعة `00_RELEASE_CONTROL.md` لنقل المهمة لحالة منجزة ويطلب موافقتك لاعتماده.

#### 4. تشغيل الدورة الكاملة المتكاملة
اكتب في المحادثة:
```text
/release-cycle
```
- يدير الوكيل دورة العمل الكاملة بالتسلسل: منسق الإطلاق -> بوابة موافقة 1 -> مهندس التنفيذ -> بوابة موافقة 2 -> مدقق الجودة -> اعتماد التحديث، مع التوقف التام عند كل بوابة بانتظار موافقتك الصريحة بكلمة "نعم".

## 5. دليل النقل والتكيف لبيئة OpenAI Codex (Codex Adaptation Guide)

في حال الرغبة في استنساخ هذا "العقل" وتطبيقه على **OpenAI Codex** (سواء عبر Codex CLI أو جلسات البرمجة المستقلة)، يوضح هذا القسم المتطلبات الدقيقة وكيفية ترجمة كل مكون ليعمل ضمن بيئة Codex.

### أ. الفروقات الهيكلية بين Antigravity و Codex

| المكون | Antigravity (`agt`) | OpenAI Codex | آلية التكيف والتطبيق في Codex |
|---|---|---|---|
| **التعليمات العامة** | قواعد آلية في `.agent/rules/` | ملف `AGENTS.md` في جذر المشروع | دمج قواعد الحوكمة مباشرة في `AGENTS.md` |
| **سير العمل (Workflows)** | ملفات `.agent/workflows/*.md` تفعل بـ `/slash` | برومبتات مخصصة أو تعليمات نظام | تحويلها إلى System Prompts أو وسوم استدعاء |
| **حقن الحالة (Context Injection)** | خطاف أصلي `PreInvocation` في `hooks.json` | لا يوجد خطاف أصلي في Codex CLI | استخدام سكربت تغليف (Wrapper) أو Orchestrator |
| **حماية الملفات (Guard Hook)** | خطاف أصلي `PreToolUse` مع اعتراض الأداة | سياسة صلاحيات CLI أو فحص Git Hooks | تشغيل Codex بنمط التأكيد الصارم أو Git Hook |
| **فحص الجاهزية (Pre-Flight)** | تشغيل عبر أدوات الوكيل | تشغيل عبر أدوات الوكيل المتاحة لـ Codex | نفس السكربت يعمل مباشرة عبر `bash` |

---

### ب. المتطلبات الهندسية لتشغيل العقل على Codex

#### 1. طبقة القواعد: ضبط `AGENTS.md`
يمتلك Codex ميزة أصيلة في قراءة ملف `AGENTS.md` تلقائياً عند بدء أي جلسة في المستودع.
**المطلوب تطبيقه:**
- التأكد من احتواء `AGENTS.md` على بند إلزامي يوجه Codex إلى الالتزام بقواعد حوكمة الإطلاق:
  ```markdown
  ## Release Governance (Labeeb v0.1)
  - Operating Mode: Shipping Mode (WIP = 1).
  - Single Source of Truth: tasks/release-v0.1/00_RELEASE_CONTROL.md.
  - Active Sprint: Located dynamically in tasks/release-v0.1/sprints/.
  - You must never modify governance files or mark tasks as completed without founder approval.
  - Roles must follow strict boundaries: Lead coordinates, Executor writes minimal scoped code, Auditor verifies live without editing code.
  ```

#### 2. طبقة حقن الحالة (State Injection) في Codex
بما أن Codex لا يمتلك محرك `PreInvocation Hooks` مدمجاً في نسخته الحالية، يتم توفير سياق الحالة عبر أحد الخيارين التاليين:

- **الخيار الأول (الموصى به - عبر أداة `orchestrator`):**
  تقوم أداة `orchestrator` بحقن الرسالة المأخوذة من `.agent/scripts/inject-release-state.sh` كـ Initial Context عند إطلاق مهمة Codex:
  ```bash
  STATE=$(.agent/scripts/inject-release-state.sh | jq -r '.injectSteps[0].ephemeralMessage // empty')
  orchestrator launch codex --cwd . --name "<TASK_ID>" "${STATE} \n\n <حزمة التذكرة والتعليمات>"
  ```

- **الخيار الثاني (سكربت تشغيل محلي `run-codex.sh`):**
  إنشاء سكربت تشغيل خفيف يغلف تشغيل Codex ويمرر له سياق المهمة الحالية في بداية الأمر:
  ```bash
  #!/usr/bin/env bash
  STATE_MSG=$(python3 -c '
  import json, subprocess
  try:
      out = subprocess.check_output([".agent/scripts/inject-release-state.sh"])
      data = json.loads(out)
      print(data.get("injectSteps", [{}])[0].get("ephemeralMessage", ""))
  except Exception:
      print("")
  ')
  codex --prompt "سياق المشروع الحالي: $STATE_MSG \n\n $@"
  ```

#### 3. طبقة حماية الملفات (Governance Guard) في Codex
في Antigravity، يقوم الـ Hook باعتراض استدعاء أداة التعديل (`replace_file_content` / `write_to_file`) تلقائياً.
**لتطبيق نفس الحماية على Codex:**
1. **تفعيل نمط التأكيد اليدوي في Codex:**
   تشغيل Codex مع إلزامية الموافقة على تعديل الملفات:
   ```bash
   codex --ask-approval
   ```
2. **استخدام Git Pre-Commit Hook:**
   تثبيت خطاف محلي في `.git/hooks/pre-commit` يمنع أي Commit يمس ملفات الحوكمة إلا بوجود متغير بيئي صريح:
   ```bash
   #!/usr/bin/env bash
   PROTECTED=("tasks/release-v0.1/00_RELEASE_CONTROL.md" "tasks/release-v0.1/01_RELEASE_CONTRACT.md" ".agent/rules/")
   DIFF_FILES=$(git diff --cached --name-only)
   for p in "${PROTECTED[@]}"; do
     if echo "$DIFF_FILES" | grep -q "$p"; then
       if [ "${ALLOW_GOVERNANCE_EDIT:-0}" != "1" ]; then
         echo "🛡️ خطاف Git يمنع حفظ تعديلات على ملف الحوكمة المحمي [$p] دون إذن صريح."
         exit 1
       fi
     fi
   done
   ```

#### 4. محاكاة مسارات العمل (Workflows) في Codex
- بدلاً من كتابة `/lead` أو `/exec` في واجهة Antigravity:
  - يمكن إنشاء اختصارات (Aliases أو Prompt Presets) مثل:
    - `codex-lead`: يستدعي Codex مع تضمين محتوى `.agent/workflows/lead.md`.
    - `codex-exec`: يستدعي Codex مع تضمين محتوى `.agent/workflows/exec.md`.
    - `codex-audit`: يستدعي Codex مع تضمين محتوى `.agent/workflows/audit.md`.
- أو من خلال كتابة العبارات الطبيعية المتفق عليها في بداية المحادثة، حيث أن قاعدة `AGENTS.md` كفيلة بتوجيهه للدور المناسب فوراً.

## 6. ملخص وجدول التوافق السريع

| الميزة | Antigravity (`agt`) | تكييفها في Codex |
|---|---|---|
| تفعيل دور منسق الإطلاق | كتابة `/lead` | كتابة `"دورك منسق الإطلاق"` أو استدعاء ملف `lead.md` |
| تفعيل دور مهندس التنفيذ | كتابة `/exec` | كتابة `"ابدأ بالتنفيذ"` أو استدعاء ملف `exec.md` |
| تفعيل دور مدقق الجودة | كتابة `/audit` | كتابة `"دورك مدقق الجودة"` مع تفعيل النمط المحايد |
| فحص الجاهزية الميدانية | `.agent/scripts/pre-flight-check.sh` | نفس السكربت تماماً (مستقل) |
| حماية ملفات الحوكمة | `PreToolUse hook` في `hooks.json` | `--ask-approval` + Git Pre-Commit Hook |
| حقن حالة المهمة الحالية | `PreInvocation hook` في `hooks.json` | تمرير رسالة السكربت عبر Wrapper أو Orchestrator |

هذا التصميم يضمن بقاء المنظومة متماسكة، خفيفة، وقابلة للنقل لأي نموذج ذكاء اصطناعي مستقبلاً دون إعادة اختراع العجلة.
