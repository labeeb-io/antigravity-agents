# Labeeb Orchestrator Integration & Offloading Plan

## 1. Vision & Architecture Overview

The primary objective is to **dramatically reduce token consumption and context bloat** within Antigravity (AGY) 2.0 Standalone during Shipping Mode discovery and audit cycles, while maintaining strict architectural boundaries and proof fidelity.

### Architectural Flow

```text
┌────────────────────────────────────────────────────────┐
│               discovery-coordinator                    │
│   - Holds the decision boundary & Proof Ledger         │
│   - Context remains 100% clean (no raw code files)     │
│   - Only issues bounded questions & receives verdicts  │
└──────────────────────────┬─────────────────────────────┘
                           │ 1. Assigns 1 exact question
                           ▼
┌────────────────────────────────────────────────────────┐
│               discovery-researcher                     │
│   - Runs on fast/light model (flash)                   │
│   - Acts as Dispatcher & Reconciler                    │
│   - Translates question into bounded Orchestrator task │
└──────────────────────────┬─────────────────────────────┘
                           │ 2. orchestrator launch
                           ▼
┌────────────────────────────────────────────────────────┐
│            @backnotprop/orchestrator CLI               │
│   - Detached process supervisor                        │
│   - Manages task IDs, logs, timeouts, interrupts       │
│   - Context consumption happens outside AGY!           │
└──────────────────────────┬─────────────────────────────┘
                           │ 3. Sandboxed execution
                           ▼
┌────────────────────────────────────────────────────────┐
│             External Worker (Codex / Claude)           │
│   - Strictly READ-ONLY / Sandboxed                     │
│   - Deep AST, symbol search, file reading, call paths  │
│   - Outputs structured finding into result.md          │
└──────────────────────────┬─────────────────────────────┘
                           │ 4. orchestrator read --wait
                           ▼
┌────────────────────────────────────────────────────────┐
│        discovery-researcher (Reconciliation)           │
│   - Reads worker summary                               │
│   - Spot-verifies exact lines/symbols with view_file   │
│   - Detects hallucinations or false claims             │
│   - Returns concise specialist_result YAML             │
└──────────────────────────┬─────────────────────────────┘
                           │ 5. Returns compact answer
                           ▼
┌────────────────────────────────────────────────────────┐
│               discovery-coordinator                    │
│   - Decides: OBSERVED_PASS | OBSERVED_FAIL | BLOCKED   │
│   - Advances Proof Ledger                              │
└────────────────────────────────────────────────────────┘
```

## 2. Read-Only & Sandboxing Enforcement

Workers launched through Orchestrator during research must **never** modify, create, or delete repository files.

### Multi-Layer Protection:

1. **CLI Level (Sandbox Flags)**:
   - For `codex exec`: Pass `--sandbox read-only` so the provider engine enforces file-system write blocks natively.
   - For `claude-code`: Run without permission-escalation flags (or via custom read-only agent configuration).
2. **Custom Agent Definition (`orchestrator.config.json`)**:
   We can define a dedicated worker agent:
   ```json
   {
     "agents": {
       "codex-researcher": {
         "adapter": "process",
         "command": "codex",
         "args": ["exec", "--sandbox", "read-only", "{prompt}"],
         "output": "text"
       }
     }
   }
   ```
3. **Prompt-Level Research Contract**:
   Every prompt generated by `discovery-researcher` starts with a mandatory invariant header:
   ```text
   [READ-ONLY RESEARCH CONTRACT]
   Objective: Inspect, trace, and report findings on the question below.
   Hard Limits: DO NOT edit, create, or delete files. DO NOT run git mutations,
   migrations, or service restarts. Report exact file paths and line numbers.
   ```

## 3. Operational Supervision & Fault Handling

How to monitor progress, catch hangs/loops, and eliminate hallucinations:

| Scenario | Detection Mechanism | Orchestrator Action / Remediation |
| :--- | :--- | :--- |
| **Worker Hangs / Stalls** | `orchestrator read <id> --wait --json` reaches timeout. | Run `orchestrator interrupt <id> --reason "timeout"` to cleanly kill the process group. |
| **Worker In Infinite Loop** | `orchestrator ps --active --json` shows excessive duration or repetitive `last` events. | Inspect `orchestrator events <id> --agent-only` then interrupt. |
| **Worker Hallucination** | Worker cites a class/file/method that does not exist or behaves differently. | **The Reconciliation Step**: `discovery-researcher` does a 1-second `view_file` on the cited path. If mismatch found, mark `UNKNOWN` or reject. |
| **Process Crash / Lost Pid** | Orchestrator supervisor marks task as `failed` or `unavailable` via `heartbeat.json`. | Researcher catches error in JSON response and returns `BLOCKED (Worker crashed)`. |

## 4. Complexity Tiers & Model Preferences

We configure `skills/orchestrator/PREFERENCES.md` with explicit task complexity levels:

### Complexity Matrix

| Tier | Purpose | Recommended Model / Runtime | Behavior / Routing |
| :--- | :--- | :--- | :--- |
| **`SIMPLE`** | Bounded symbol search, config lookup, route existence | Fast / Efficient Codex (e.g. `codex` default / mini) | Low latency, minimal token spend. |
| **`MEDIUM`** | Cross-class call path, middleware pipeline, service flow | Standard Codex (`codex` standard model) | Accurate AST & code comprehension. |
| **`COMPLEX`** | Multi-service orchestration, concurrency, event chains | High-capability Codex or Claude Code | Deep architectural reasoning. |
| **`REVIEW`** | Independent audit / Challenger pass | **Alternative Provider** (e.g. Claude Code if implementer was Codex) | Prevents model blind spots & self-confirmation bias. |

### Definition in `PREFERENCES.md`
```markdown
## User Preferences

- For SIMPLE code lookups and route verifications, use the fastest available Codex model.
- For MEDIUM code tracing across Laravel and Cloudflare services, use standard Codex.
- For COMPLEX multi-module logic or architectural dependency questions, use highest capability Codex or Claude Code.
- For REVIEW or independent audit challenges, always select an alternative provider from the implementer (e.g. Claude Code for reviewing Codex work).
- When a task requires read-only research, enforce read-only sandboxing.
```

## 5. The Reconciliation Contract (`discovery-researcher`)

The core innovation that keeps AGY clean and reliable:

```text
Worker (Codex/Claude)
         │
         ▼ Output: "Function handleAuth() in app/Http/Middleware/VerifyEdge.php:45 rejects tokens without header X"
         │
         ▼
discovery-researcher (Spot Verification)
         │
         ├─→ Calls: view_file(VerifyEdge.php, StartLine: 43, EndLine: 48)
         │   (Consumes only ~50 tokens inside AGY!)
         │
         ├─→ Verified: True
         │
         ▼
discovery-coordinator
         │
         ▼ Receives:
         specialist_result:
           question: "Does VerifyEdge require header X?"
           state: ANSWERED
           answer: "Yes, verified at VerifyEdge.php:45."
           confidence: high
```

## 6. Advantages of Orchestrator Over Direct Model Calls

1. **Durable Task Store**: Every run is persisted in `~/.orchestrator/tasks/<id>/` with full `stdout.log`, `stderr.log`, `events.jsonl`, and `result.md`.
2. **Process Isolation**: External CLI workers run in their own process groups; a crash or stall never crashes AGY.
3. **Token Decoupling**: Large codebases (thousands of lines read by Codex) do not enter AGY's context window.
4. **Deterministic Commands**: Native support for `launch`, `ps`, `watch`, `logs`, `events`, `read --wait`, and `interrupt`.
5. **Codex Sessions**: When a problem requires multi-turn investigation, `codex-app-server --session` provides persistent provider threads without rebuilding context.
