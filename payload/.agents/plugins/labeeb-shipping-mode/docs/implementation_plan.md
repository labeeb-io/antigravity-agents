## ⚠️ قائمة المخاطر العالية المعزولة (High-Risk Items)
*تم عزل هذه النقاط من الدراسة لمنع أي ثغرات أو حلقات لا نهائية أثناء الأتمتة:*

1. **🔴 خطر التدقيق الذاتي في الجلسة الواحدة (Self-Auditing Blind Spot):**
   - *الخطر:* إذا نفّذ الوكيل الكود ودققه في نفس الجلسة بـ `/release-cycle`، يقع في فخ "تأكيد الذات".
   - *الضابط الصارم:* حظر التدقيق في نفس الجلسة للمهام عالية الخطورة (Auth, Schema, Routing, Cloudflare). للمهام العالية، يُلزم النظام المؤسس بفتح جلسة تدقيق مستقلة أو إسناد المراجعة لنموذج مستقل (Bifrost / Claude Opus).
2. **🔴 خطر الحلقات اللانهائية باعتراض الإيقاف (`force_continue` & Stop Hooks):**
   - *الخطر:* فحص الترانزكريبت بحثاً عن كلمات وإجبار الوكيل على المتابعة عبر `force_continue` قد يسبب حلقات لا نهائية تستهلك الرصيد وتجمد الجلسة.
   - *الضابط الصارم:* **استبعاد وإلغاء `force_continue` تماماً**. الانتقال بين المراحل مشروط دائماً ببوابة موافقة بشرية صريحة.
3. **🔴 خطر حظر التعديل الخاطئ (`PreToolUse Deny Bug`):**
   - *الخطر:* خطأ في سكريبت `guard-governance-files.sh` قد يمنع تعديل ملفات كود شرعية أو يعطل العمل.
   - *الضابط الصارم:* فحص السكريبت محلياً وحصر المنع الصارم في ملفات الحوكمة الأساسية فقط وفصلها بحسب الدور.
4. **🔴 خطر تلف لوحة المتابعة المركزية بالهلوسة (`Auto-Corrupting Control State`):**
   - *الخطر:* قيام الوكيل بتعديل `00_RELEASE_CONTROL.md` آلياً بدون مراجعة بشرية قد يخرب جداول الماركداون.
   - *الضابط الصارم:* يقتصر دور الوكيل على صياغة مقترح التعديل (`Git Diff`) وتطبيقه مشروط بموافقة المؤسس.
